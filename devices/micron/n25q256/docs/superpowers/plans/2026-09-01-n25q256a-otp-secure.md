# N25Q256A OTP Secure Function Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement safe N25Q256A 64-byte OTP programming and optional permanent locking through `SECURE_FUN`.

**Architecture:** Represent OTP as one 65-byte special block whose last byte carries the lock request. `SecureFun` programs and verifies the 64 data bytes first, then separately locks and verifies the control byte only when requested.

**Tech Stack:** ARM RVDS C, ALL-1000 firmware block tables, FPGA gang SPI primitives, Windows batch build.

## Global Constraints

- OTP data addresses are `00h-3Fh`; OTP control address is `40h`.
- Use `42h` for program and `4Bh` for read.
- Send four address bytes because PowerOn leaves the device in 4-byte address mode.
- READ OTP sends one dummy byte after the address.
- Never lock before all still-passing sockets verify their OTP data.
- Publish BIN/SPC to `D:\Hi-Lo\ALL1000\Algo1`.

- [ ] **Step 3: Implement VerifyOTPArray**

The helper must transmit `4Bh`, four address bytes, one dummy byte, configure the FPGA mask, compare `Count` bytes across all enabled sockets, and close CS on every return path.

Run the build and expect no implicit-declaration, unused-variable, or syntax diagnostics.

### Task 3: Implement the two-phase SecureFun

**Files:**
- Modify: `WAx4_N25Q256Ax3ESFxxx.c`

**Interfaces:**
- Consumes: `ProgramOTPArray`, `VerifyOTPArray`, `CFCardReadWordData`.
- Produces: functional `uChar SecureFun(void)`.

- [ ] **Step 1: Remove the unreachable TH/GD implementation**

Delete the early `return SUCCESS` and all SR2/LB1-LB3 code.

- [ ] **Step 2: Load the 65-byte secure payload**

Read 32 words for OTP bytes `0-63`, then use the low byte of the 33rd word as the control request.

- [ ] **Step 3: Program and verify OTP data**

Program address zero with exactly 64 bytes. Verify the same 64 bytes before considering the lock request.

- [ ] **Step 4: Apply optional permanent lock**

If control bit0 is zero, restore the current passing-socket mask, program one byte `FEh` at address `40h`, and verify control bit0 using mask `01h`.

- [ ] **Step 5: Report failures**

Set `SysStatusCode = E_SecureFail` and return `FAIL` when every socket fails. Preserve partial-socket gang behavior.
