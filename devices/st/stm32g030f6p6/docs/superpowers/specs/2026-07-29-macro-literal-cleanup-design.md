# WJ_STM32G030F6P6.c 宏与十六进制常量整理设计

## 目标

整理整个 `WJ_STM32G030F6P6.c` 的宏定义，使高频及具有重要硬件语义的值继续使用具名宏，而低频掩码、位值、延时和固定控制数据直接在使用位置写成带注释的十六进制常量。

本次只改善代码表达，不改变 SWD 时序、寄存器访问顺序、多工位处理、错误处理或烧录行为。

## 保留规则

以下宏不以引用次数作为唯一判断依据，原则上保留：

- STM32G0 寄存器地址，如 `FLASH_CR`、`FLASH_SR`、`FLASH_KEYR` 和 `FLASH_OPTR`。
- SWD DP/AP 请求命令，如 `DPACC_*` 和 `APACC_*`。
- Flash 和 Option Byte 解锁键。
- 芯片固有参数，如 Flash 起始地址、容量、页大小和总页数。
- 在多个函数或多个表达式中重复使用的状态值、错误掩码和协议常量。
- 直接表达硬件身份或协议含义、内联后容易误用的重要常量。

## 内联与删除规则

- 只使用一至两次、且仅表示局部掩码、位值、固定控制数据或延时的宏，改成带 `UL`/`L` 等原有类型后缀的十六进制常量。
- 每个内联值在首次或唯一使用处添加简短注释，说明对应寄存器位或协议含义。
- 不把地址、密钥或 SWD 命令改成无说明的魔数。
- 完全未被实际代码引用、只用于拆解说明且已有组合常量覆盖的宏直接删除。
- 对由多个宏组合而成且多处使用的掩码，继续保留组合宏，避免重复长表达式。

## 修改范围

修改仅限：

- `WJ_STM32G030F6P6.c` 顶部宏定义区域。
- 因宏内联而必须调整的对应使用位置与注释。

不修改：

- `.h`、`.spc`、FPGA 文件或工程配置。
- 函数接口和全局变量。
- Protect、Program、Erase 等功能的控制流程和输入校验策略。

## 验证

完成修改后执行：

1. 搜索被删除宏的残留引用。
2. 检查所有内联常量的数值、位宽和类型后缀与原宏一致。
3. 审阅 `git diff`，确认没有功能性语句重排或控制流变化。
4. 使用项目现有构建入口编译；若旧工具链无法在当前环境运行，则至少完成预处理/语法层面的可用检查，并明确报告限制。

## 完成标准

- 高频及重要硬件语义宏仍然清晰可见。
- 低频简单宏不再迫使读者频繁跳转到文件顶部查询。
- 所有内联十六进制值均有足够的就地说明。
- 构建结果不因本次整理新增错误。
- 运行行为与整理前一致。
